# 写前冻结：术语表与唯一归属

Phase 4 的产出，落在 `.work/freeze/`。两个文件，半小时成本，换掉的是后面几百处替换和重复贴代码。

**为什么必须动笔前做**：写手分散在多个子 agent 里，彼此看不到对方用了什么词。不冻结，同一个概念会同时存在 `chunk` / `证据` / `文档片段` 三种写法，同一份枚举会在两篇里各贴一遍——改一处漏一处。等写完再统一，要全库搜一遍，改几百处。

## 术语表 `glossary.md`

**谁写**：Vera Cross（Phase 4）

**格式**（照抄，不要发明）：

```markdown
## <分组名>

**<正名>**：
<一句话定义，说清「它是什么」，不写「它很重要」>。
_Avoid_: <避用词1>, <避用词2>, <英文或旧称>
```

分组按书的结构走（接入 / 业务 / 数据 / 基础设施之类）。

**三条规则**：

1. **一个概念只有一个正名。** 同义表达进 `_Avoid_`，不许「两种都能用」。
2. **代码标识符不进 `_Avoid_`。** `chunk_id`、`chunks` 表、`CHUNK_SIZE` 是代码，一律不动；只有**中文散文里**的 `chunk` 才该写成「切片」。
3. **首现要给定义。** 每章第一次出现术语时补一句「它是什么」，之后直接用，不再解释。

**怎么选出该冻结的词**：扫 Phase 2/3 的全部文档，凡是**同一件事出现两种以上叫法**的，就是候选。只冻结真正会漂移的，不要把普通名词全列进来——词表越长越没人看。

## 唯一归属表 `ownership.md`

**谁写**：Vera Cross（Phase 4）

**格式**：

```markdown
| 被归属物 | 唯一归属文件 | 其他章节怎么处理 |
|---|---|---|
| `ErrorCode` 完整枚举 | `03-具体实现/02-工程可维护性/03-具体实现.md` | 其余章只写「见该篇」，不重贴 |
| `DocumentParser` 抽象基类 | `03-具体实现/03-文档处理链路/02-功能流程与架构.md` | 具体实现篇只写实现要点 + 指路 |
| 档位预设参数表 | `03-具体实现/05-性能优化/02-功能流程与架构.md` | 别章写「本期参数见第 5 步」，不复制表格 |
```

**四条规则**：

1. **一个事实 / 一个代码块 / 一张表，只能有一个 owner。**
2. owner 选**读者最可能停下来研究它的那一篇**。
3. 非 owner 章节写三件事：**本步的增量** + **一句指路** + **本步特有的坑**。
4. 跨篇复用同一张图可以（图不占正文语义）；**代码和表格不行**。

**怎么找候选**：Phase 3 深挖时，凡是「完整枚举 / 抽象基类 / 参数表 / 建表语句」这类会被整段搬走的东西，都列进来。

## 交稿前自检（Phase 5 每批、Phase 6 汇编前各跑一遍）

1. 每篇恰好一个 H1，层级不跳级。
2. 附录编号连续、风格唯一（只用「附一 / 附二」）。
3. 四件套导航不链接自己（写「本篇（你在这里）」），且 `00` → `01` → `02` → `03` 顺序可达。
4. 中文散文里没有 `_Avoid_` 列出的词（代码标识符除外）。
5. 代码块与表格的 owner 唯一，非 owner 处是指路而不是重贴。
6. 单篇 ≤ 600 行；600–900 行加「本章怎么读」导航表；> 900 行拆文件。
7. 无 Mermaid、无字符画、无内联 SVG 源码——图一律 `.svg` 文件 + 相对路径。
8. 相对链接可达；跨目录用 `../目录/文件名`，同目录直接写文件名。
